# agent2kaggle

Агент Kaggle, доступный по [A2A](https://a2a-protocol.org): карточка отдаётся
статически, вызовы идут JSON-RPC на `POST /a2a`. Развёртывается на Netlify
Functions.

## Что он делает

| навык | что возвращает |
|---|---|
| `submissions` | последние сабмиты соревнования: время, статус, публичный скор, лучший результат |
| `kernel-status` | состояние прогона по слагу `owner/kernel-name` |

## Чего он не делает, и это осознанно

Сабмиты, запуск кернелов и правку файлов сюда не вынесли. Причины:

- отправка расходует дневной лимит и в пределах суток необратима;
- ожидание прогона длится часами — бессерверная функция не то место, где такое
  должно жить;
- утёкший адрес эндпоинта тогда позволяет **прочитать** состояние, но не
  **потратить** его.

Оба оставшихся навыка — один быстрый запрос к Kaggle каждый, они укладываются в
одну инвокацию и завершаются синхронно. Поэтому хранилища задач нет, и
`tasks/get` честно отвечает, что задачи выполняются синхронно, вместо того чтобы
изображать несуществующее состояние.

## Авторизация в Kaggle: две несовместимые схемы

У Kaggle два вида учётных данных, и они **не взаимозаменяемы**:

- **access token** — одна строка (~37 символов, префикс `KG`) в
  `~/.kaggle/access_token`. Принимается **только** как `Authorization: Bearer`.
- **классическая пара** `username` + `key` из `kaggle.json`. Принимается как Basic.

Проверено на живом API: с access-токеном `Bearer` даёт 200, `Basic` с той же
строкой — 401. Функция предпочитает `KAGGLE_ACCESS_TOKEN`, откатывается на
`KAGGLE_USERNAME`+`KAGGLE_KEY` и падает с внятной ошибкой, если нет ни того ни
другого, — вместо того чтобы отправить заголовок, который API молча сочтёт
анонимным.

## Переменные окружения

| Имя | Назначение |
|---|---|
| `A2A_TOKENS` | пропуска вызывающих: `имя:токен` через запятую |
| `A2A_TOKEN` | одиночный пропуск, если вызывающий один |
| `KAGGLE_ACCESS_TOKEN` | новая схема, предпочтительна |
| `KAGGLE_USERNAME`, `KAGGLE_KEY` | классическая схема, запасной вариант |
| `DEFAULT_COMPETITION` | необязательный слаг по умолчанию |

Только через переменные окружения. В репозиторий не класть: `.env` и
`.secrets/` в `.gitignore`.

Токен Kaggle не ограничивает полномочия — он позволяет и сабмитить, и пушить
кернелы. Эндпоинт использует его только на чтение, но при утечке отзывать
придётся весь. Для публичного края разумнее завести отдельный токен.

## Как подключить другого агента

Вызывающему нужны две вещи: адрес и свой пропуск. Ничего больше — карточка
публична и сама сообщает, где эндпоинт и какие есть навыки.

**Выдать пропуск.** Каждому вызывающему — свой, иначе отозвать доступ одному
нельзя, не сломав всех, и в логах не видно, кто звал:

    npx netlify-cli env:set A2A_TOKENS "alice:$(openssl rand -hex 32),bob:$(openssl rand -hex 32)"

Отозвать доступ — убрать пару из списка и выложить заново. В логах функции
каждый вызов помечен именем: `a2a: caller=alice method=message/send`.

**Проверить с той стороны:**

    A2A_TOKEN=<пропуск> node client.mjs https://<host> "rsna-knee-abnormality-detection"

`client.mjs` делает ровно то, что должен делать вызывающий агент: читает
карточку по `/.well-known/agent-card.json`, берёт адрес **из неё**, а не
зашивает, и вызывает `message/send`.

**Из браузера** — тоже работает: на `/a2a` обрабатывается preflight, ответы
несут `Access-Control-Allow-Origin`.

Сравнение токенов постоянное по времени: проверка с ранним выходом выдавала бы
префикс пропуска по времени ответа.

## Чат агентов

`/chat.html` — общая лента в стиле терминала: справа наш `kaggle`, слева
вызывающий агент, реплики людей — отдельным цветом.

Лента не отдельная от A2A, а та же самая: `POST /a2a` пишет в неё и запрос
вызывающего, и ответ агента. Поэтому страница показывает **настоящую переписку
агентов**, а не человеческий чат рядом с невидимым обменом. Запрос ложится в
журнал до выполнения — если вызов упадёт, в ленте всё равно видно, о чём просили.

Кто угодно с тем же токеном открывает страницу, видит всю историю и может
написать сам, предварительно указав имя. Отдельной роли для людей нет намеренно:
иначе пропусков стало бы два, а отзывать пришлось бы оба.

| эндпоинт | назначение |
|---|---|
| `GET /api/chat?since=<seq>` | сообщения после курсора |
| `POST /api/chat` | `{author, text}` — реплика человека |

Хранилище — Netlify Blobs, лента обрезается до последних 500 сообщений.

## Развернуть

    export NETLIFY_AUTH_TOKEN=<личный токен доступа Netlify>
    ./deploy.sh <имя-сайта>

Если сайт уже создан в Netlify, передайте его имя — скрипт подключится к нему,
а не станет создавать новый.

Скрипт создаёт сайт, проставляет переменные из `.env` и `.secrets`, выкладывает
и сам себя проверяет: карточка, отказ без токена, успешный вызов с токеном.

## Проверить вручную

    curl -s https://<host>/.well-known/agent-card.json | jq .

    curl -s https://<host>/a2a \
      -H "Authorization: Bearer $A2A_TOKEN" \
      -H 'content-type: application/json' \
      -d '{"jsonrpc":"2.0","id":1,"method":"message/send","params":{"message":
           {"role":"user","kind":"message","messageId":"1",
            "parts":[{"kind":"text","text":"rsna-knee-abnormality-detection"}]}}}' | jq .

Вызов без заголовка должен вернуть отказ — это тоже проверка.

## `aquarium/`

Определение той же рыбки для платформы [A-quarium](https://github.com/): карточка,
промпт и конфиг виртуального сервера инструментов. Там агент получает то, чего
у бессерверного края нет: очередь, дневной бюджет и подтверждение человеком
перед тратой.

Промпт стоит прочитать отдельно: в него вынесено то, что этот агент знает про
соревнования и что стоило дорого — как отличить отложенную выборку от
тюнинг-сета, почему бутстрап на выбранном весе завышает результат примерно
вдвое, и почему декорреляция не заменяет силу.
